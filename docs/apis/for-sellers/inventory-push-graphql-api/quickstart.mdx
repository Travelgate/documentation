# Quickstart

:::note New API

The **Inventory Push Sellers API** is intended for suppliers that already have a push-based integration model. In this flow, the provider loads availability, rates, and pricing information into Travelgate’s **Inventory** database. Once the product is stored in Inventory, connected Buyers can consume it through different channels and integration models according to their needs.

This model is used when the Seller wants to publish its product to the Travelgate network by sending updates into our Inventory. The connector can be developed by **Travelgate**, or the Seller can implement our API directly to load the product data into our Inventory system.

:::

## Introduction

This GraphQL API is designed for suppliers that need to push product data into Travelgate’s Inventory system. Instead of exposing real-time availability and pricing directly to Buyers through a pull model, the supplier sends the data to Travelgate, where it is stored and managed centrally.

From there, Buyers can access the product in multiple ways, depending on the commercial setup and their own connectivity model. The result is a centralized inventory layer that makes it easier to maintain consistency, automate updates, and expose the same product data to different buyers and channels.

This API mirrors the capabilities available on our existing [Inventory Extranet](/docs/apps/inventory/extranet/overview), with the added advantages of API automation, scalability, and reduced manual effort.

The Inventory Push Sellers API supports the complete setup and maintenance of hotel product information, including:

* **Hotels and master data**
* **Rates and room configuration**
* **Availability and closing conditions**
* **Pricing and occupancy logic**
* **Structured updates to Travelgate Inventory**

This model is especially useful when a supplier wants to push product information to Travelgate and then let Buyers consume that data through their preferred integration path, without requiring each Buyer to integrate directly with the supplier’s own system.

## Integration Approaches: Understanding Setup Models

This API supports different integration models adapted to your business needs. Depending on your channel manager or connectivity strategy, you can understand which approach best suits your workflow.

### Push Integration in Inventory

This seller guide focuses on **Push** integrations for generic supplier developments. The Push integration type is the primary approach for this API, where your system proactively sends updates to Travelgate's Inventory.

### Setup Approach

This flow explains how the setup is created and maintained in Inventory. Depending on the integration, setup can be manual, fully automated, or partially automated:

#### Manual SetUp
The traditional approach used by legacy integrations. In this model:
- Setup is managed **manually** by the client or authorized hotel users through the Inventory Extranet
- No automation occurs—all data entry, updates, and master information management is done directly by users
- Requires significant manual effort and time investment

#### Full AutoSetUp (recommended)
A modern, fully automated integration model where the integration implements the complete setup using provider information:
- The integration automatically loads and manages all hotel data, rates, rooms, and related properties into Inventory
- **Clients do not need to perform any manual setup tasks**—everything is handled by the integration
- Significantly reduces time to production and eliminates manual data entry errors
- Provider information is leveraged to fully populate the inventory without any client intervention
- Ideal for providers and channel managers that provide complete data sets
- **Why we strongly recommend it**: Full AutoSetUp minimizes onboarding friction, removes manual product loading tasks for clients, and helps them start purchasing your inventory faster.

#### Partial AutoSetUp
A partially automated approach where some setup elements require manual configuration:
- The integration handles certain aspects of the setup automatically using provider data
- However, some data may not be available directly from the provider and must be provided by the client first (e.g., hotel codes)
- Once the required information is provided, the integration retrieves and loads the remaining related setup data
- Useful for scenarios where provider data is partially complete
- Reduces manual work while maintaining flexibility for data that requires client specification

Each setup approach offers distinct advantages depending on your integration capabilities and data availability.

### Booking Flow Approach

Once the setup is ready in Inventory, **Inventory manages the booking lifecycle** for Push integrations. Your integration should process booking notifications from Inventory, or retrieve bookings from Inventory, to keep your platform synchronized. Keep in mind that booking notifications support all payment types, while booking retrieval works only with Merchant payment.
