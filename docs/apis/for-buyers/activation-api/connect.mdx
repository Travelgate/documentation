# Connect

Use `connect` to submit the buyer-side activation request. The input type is `ActivationConnectInput`.

## Buyer Input Context

Build the request with:

- `organizationBuyerCode` (required) — your buyer organization code, from `allOrganizations` where `isBuyer = true`.
- `group` (optional) — your HotelX Instance code.
- `notificationEmail` (optional) — addresses notified when the activation completes.
- `accessConfiguration` (required, `AccessInput`) — at minimum `supplier`, and the `parameters` (`key`/`value` pairs) required by that supplier, as discovered in [Get Runtime Configuration](runtime-configuration.mdx).

## Runtime-to-Connect Mapping

Use the `tagRuntime` values returned by `hotelX.runtimeConfiguration` to decide where each value must be sent in `accessConfiguration` for `connect`.

| `tagRuntime` | Field in `accessConfiguration` | Notes                                        |
| ------------ | ------------------------------ | -------------------------------------------- |
| `USER`       | `user`                         | Supplier user credential                     |
| `PASSWORD`   | `password`                     | Supplier password credential                 |
| `URLGENERIC` | `urls.generic`                 | Valid URL for all methods                    |
| `URLAVAIL`   | `urls.search`                  | Availability URL                             |
| `URLQUOTE`   | `urls.quote`                   | Valuation URL                                |
| `URLBOOK`    | `urls.book`                    | Booking URL                                  |
| `PARAMETER`  | `parameters[]`                 | Parameters as `{ key: "...", value: "..." }` |

## Mutation Overview

```graphql
mutation Connect($data: ActivationConnectInput!) {
  activation {
    connect(data: $data) {
      code
      activationData {
        status
      }
    }
  }
}
```
